1. نظرة عامة على المشروع

AraLink هو أداة ترجمة ذكية تترجم أي محتوى من رابط — فيديوهات يوتيوب، مقالات، مواقع ويب، ملفات مستندات، نصوص عادية، حتى صور (OCR). الواجهة بالعربية (RTL) بالكامل.

القدرات الرئيسية

  • ترجمة فيديوهات YouTube (استخراج النص المترجم → عرض الترجمة مع التوقيت)
  • ترجمة المقالات والمدونات (جلب الصفحة → استخراج النص → ترجمة)
  • ترجمة أي موقع إلكتروني (جلب → تنظيف → ترجمة → عرض جنباً إلى جنب)
  • ترجمة ملفات (txt, docx, xlsx, csv, srt, vtt, json, xml, epub, pptx)
  • تحويل النص إلى كلام (TTS) بأصوات طبيعية
  • تحويل الصور إلى نص (OCR)
  • تشبيك الفيديو بالعربية (Dubbing) مع مزج صوتي
  • ترجمة النصوص مباشرة بدون رابط
  • اكتمال ذكي للترجمة عبر SSE Streaming
  • امتداد Chrome للترجمة الفورية داخل المتصفح
  • لوحة تحكم للمدير مع إحصائيات و Charts
  • نظام مشاريع مع قاعدة بيانات SQLite
  • عمليات خلفية مع طابور مهام (Job Queue)
  • تعريب النص العربي (Tashkeel)

3. البنية الخلفية (Backend)

نقطة الدخول — server/server.js (259 سطر)

Express 4.x مع CommonJS. ترتيب Middleware حرج:

تسلسل Middleware

  • 1. CORS (قائمة أسماء مصادر مسموح بها)
  • 2. Helmet (عناوين أمان CSP)
  • 3. Rate Limiter الأساسي (/api)
  • 4. Rate Limiter الثقيل + routes-file (قبل json — 15MB)
  • 5. routes-local-video (قبل json — 60MB)
  • 6. routes-ocr (قبل json — 15MB)
  • 7. express.json({ limit: '2mb' })
  • 8. routes-SSE (قبل compression!)
  • 9. routes-youtube-dub SSE + routes-jobs SSE
  • 10. compression() — gzip 60-80%
  • 11. Static files من public/
  • 12. باقي المعالجات: translate, tts, dub, projects...
  • 13. معالج الأخطاء العام (413, JSON, 500)

ملاحظات مهمة

  • routes-SSE يجب أن يكون قبل compression لأن SSE نص قابل للضغط
  • routes-file و routes-local-video و routes-ocr تأتي قبل express.json لتحديد حجم الجسم
  • الكشف عن انقطاع العميل عبر res.on('close') وليس req.on('close')
  • الوصول للدوال عبر translate.detectLanguage(...) وليس استيراد مباشر

6. الأمان (Security)

🔒 CORS

  • قائمة أسماء مصادر مسموح بها عبر CORS_ORIGIN
  • فارغ = نفس الأصل فقط (الوضع الآمن الافتراضي)
  • بدون ترويسة Origin = تمرير بدون عناوين CORS

🛡️ SSRF Protection

  • حجب جميع نطاقات خاصة (RFC 1918/loopback/link-local)
  • حماية DNS rebinding عبر undici Agent
  • إعادة التحقق عند كل توجيه (redirect)
  • 237 سطر من كود الحماية المفصل

⏱️ Rate Limiting

  • أساسي: 20 طلب/دقيقة/عنوان IP
  • ثقيل: 10 طلبات/دقيقة/عنوان IP
  • دبلجة: 60 طلباً/دقيقة/عنوان IP
  • مضاعف 3x ل holders مفاتيح API
  • Retry-After header على 429

🔐 مصادقة المدير

  • crypto.timingSafeEqual (constant-time)
  • كعكة httpOnly, SameSite=Strict (12 ساعة)
  • بدون ADMIN_TOKEN = جميع routes تُرجع 503
  • تحذير إذا الرمز < 16 حرف

11. ملاحظات وتوصيات

✅ نقاط القوة

  • بنية معمارية ناضجة ومحددة
  • 57 ملف اختبار — تغطية شاملة
  • حماية أمان مفصلة (SSRF, Rate Limit, CSP, httpOnly cookies)
  • 6 مزودين ترجمة مع آلية تراجع ذكية
  • تخزين مؤقت فعال (ذاكرة + ملف)
  • انهيار رحيم — كل ميزة اختيارية لها بديل تلقائي
  • واجهة عربية RTL كاملة مع نظام تصميم موثق
  • عمليات خلفية مع طابور مهام و-SSE
  • حماية SSRF مفصلة (237 سطر) مع DNS rebinding
  • بنية المزودات — إضافة مزود = ملف واحد

⚠️ ملاحظات

  • لا يوجد أداة قياس التغطية (coverage) متكاملة
  • node:sqlite لا يزال تجريبياً في Node 22
  • لا يوجد TypeScript — ESLint يعوّض的部分
  • الملفات الثابتة (stats-log.json, usage.json) — مناسبة لنسخة واحدة فقط
  • بعض الارتباطات الثقيلة (@xenova/transformers, tesseract.js) — Docker يتعامل معها
  • الrequire() في try/catch في أجزاء — مقصود للتهيئة الكسولة واختبارات
  • نظام الأنواع المزدوج: CommonJS للخادم + ES Modules للواجهة (مقصود لتوافق Node 22)
