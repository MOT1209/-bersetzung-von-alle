1️⃣ الحكم العام

💬 Comment — قابل للدمج بعد تنظيف شجرة git. كود الدبلجة الجديد حقيقي (ffmpeg مزج ودمج + E2E ينتج MP4 قابلًا للتشغيل)، والأمان محافظ عليه، ولا توجد عيوب منطقية مانعة. المشكلة الوحيدة الحرجة ليست في الكود بل في خلط حذف .claude/skills/ (~22 ألف سطر) مع ميزة الدبلجة في نفس الشجرة — يجب فصله في commit مستقل قبل أي دمج.

2️⃣ ما تم بشكل جيد 🎉

  • خط أنابيب حقيقي لا Mock: server/dubbing/dubbing-pipeline.js ينفذ transcript → ترجمة → TTS → timing → mix → mux إلى projects/{id}/dubbed-ar.mp4، واختبار E2E يولّد MP4 ويفحصه بـ ffprobe.
  • لا Base64 للفيديو: النتيجة ملفات تُخدم عبر /api/projects/:id/:file بأسماء آمنة (regex) — مطابق للمواصفة.
  • إعادة استخدام لا إعادة بناء: الترجمة عبر translateTextWithMeta (سلسلة الاحتياط + كاش)، التفريغ عبر audio.js، التنزيل عبر downloader.js — لا تكرار.
  • أمان سليم: فحص videoId فقط (allowlist يوتيوب)، كل استدعاءات ffmpeg عبر execFile (بلا shell)، مسارات مشاريع مُطهّرة، حد حجم فيديو مُصحَّح (1048576M←1024M)، مسار SSE قبل compression.
  • Fallback واعٍ: Gemini Video → captions → Whisper مع cooldown يمنع ضرب الحصة الميتة داخل نفس الـ job.
  • إصلاحات جانبية صحيحة: harness اختبار srtCap (حد 2MB + معالج input-too-large)، إضافة youtube-studio.js إلى SW precache.

5️⃣ الأمن (OWASP — ما فُحص فعلًا)

  • ✅ SSRF: يوتيوب مقيّد بـ videoId (لا URLs حرة)، وfetchContent المثبّت سابقًا لم يُمس.
  • ✅ Injection: كل ffmpeg عبر execFile بمصفوفة وسائط؛ أسماء الملفات والمشاريع بـ regex صارمة.
  • ✅ Path traversal: فحص startsWith(PROJECTS_DIR) + أنماط آمنة.
  • ✅ DoS: حد حجم فيديو (مُصحَّح)، سقف 5 لغات/طلب، دفعات TTS محدودة، rate limit قائم.
  • ⚠️ لم يُفحص: اختراق حمولات TTS ضخمة لكل مقطع، سباق تنزيلين لنفس المشروع، صلاحيات قراءة مشاريع الغير (أي عارف للـ ID يقرأ — مقبول لـ MVP بلا auth).
