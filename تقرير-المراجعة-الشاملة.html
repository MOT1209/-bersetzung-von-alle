الخلاصة

المشروع سليم بنيويًا ومُختبَر جيدًا: الخادم يقلع خلال ~4 ثوانٍ، حد الطلبات يعمل فعليًا (تحقّقنا بضغط حي حتى 429)، رؤوس الأمان كاملة (CSP، HSTS، nosniff…)، حماية SSRF نموذجية، ولوحة الأدمن محمية بقفل تدريجي ومقارنة ثابتة الزمن. لا نتائج حرجة تُعطّل المستخدم.

أما المشاكل المكتشفة فثلاث فئات: (1) ثغرتان أمنيتان متوسطتان — واجهة الوظائف بلا مصادقة، ومكتبة protobufjs بها ثغرة تنفيذ كود حرجة وصلت عبر تبعية صوتية؛ (2) انحراف توثيقي واضح — شارة الاختبارات في README قديمة (624 والفعلي 655) ووصف نظام الوكلاء ثابت على البنية القديمة (12 وكيلًا والفعلي 300)؛ (3) غياب كامل لملفات اكتشاف محركات البحث والذكاء الاصطناعي (robots.txt، sitemap، llms.txt) في تطبيق قائم على الظهور العام.

🚨 النتائج — مرتبة حسب الأثر

1. ثغرة تنفيذ كود حرجة (critical) في protobufjs وصلت عبر sherpa-onnx مكسور — أمني
أين
شجرة التبعيات: sherpa-onnx → protobufjs ≤7.6.2 — تحذير npm audit: «Arbitrary code execution in protobufjs» (GHSA-xq3m-2v4x-88gg).
المسار من الخارج
محرك التفريغ الصوتي (STT) هو الافتراضي (STT_ENGINE=sherpa)، وملفات نموذجه (onnx) تُنزَّل من الإنترنت عند أول تشغيل. نموذج مُلاعَب به أو بديل مُنزَّل قد ينفّذ كودًا على الخادم عبر محرك protobuf.
الأثر
تنفيذ كود عشوائي على جهاز الخادم — أسوأ أنواع الثغرات.
الإصلاح
تشغيل npm audit fix (يرفع protobufjs فوق 7.6.2) ثم اختبار STT. لو لم يكفِ: overrides في package.json أو ترقية sherpa-onnx.
الثقة
شوهدها — خرج npm audit --omit=dev الحالي.
2. كل نقاط نهاية الوظائف /api/jobs/* بلا أي مصادقة — أي شخص يقرأ تفاصيل وظائف غيره ويلغيها مكسور
أين
server/routes-jobs.js:16,22,64 — GET /api/jobs وGET /api/jobs/:id وGET /api/jobs/:id/stream لا تفحص أي توكن.
المسار من الخارج
وظائف المشاريع (تفريغ صوتي/دبلجة) تُطلق عبر POST /api/projects/:id/process المحمي بملكية المشروع، لكن ثمّة فقط. أي طرف يعرف/يخمّن معرّف الوظيفة (UUID عشوائي — يصعّب التخمين لكنه ليس سرًّا: يظهر في روابط الاستجابة 202 التي تُسجَّل في الشبكات والسجلات) يستطيع قراءة تقدمها وحالة النتائج والاطلاع على أسماء الملفات، وGET /api/jobs يُسرد كل الوظائف النشطة دفعة واحدة بلا مصادقة إطلاقًا.
الأثر
تسريب معلومات عن أنشطة المستخدمين (أرقام مشاريع، لغات، أنواع معالجة) وإمكانية إلغاء وظائفهم أثناء التشغيل.
الإصلاح
فحص ملكية الوظيفة (توكن المالك أو ربط الوظيفة بمشروع يُتحقق منه) في routes-jobs، و/api/jobs للإدمن فقط.
الثقة
شوهدتها في الكود؛ معرّف عشوائي يخفف من السهولة لكن القائمة الإجمالية تبقى مكشوفة.
3. README يقول «624 اختبارًا» والفعلي 655 — ووصف نظام الوكلاء قديم كليًا انحراف توثيقي
أين
README.md — الشارة «tests-624 passing»، جدول الجودة «624»، قسم البنية «agents/ — نظام الوكلاء المتعدد (12 رئيسي × 2 فرعي)» وقسم الوكلاء نفسه؛ بينما النظام الفعلي بعد اليوم: 300 وكيل (100 رئيسي × 2 فرعي، 20 فرقة) و655 اختبارًا (شوهدتا في خرج npm test وnode agents/index.js stats).
الأثر
من يقرأ README ليثق بالمشروع يرى رقمًا أقل من الحقيقة وتعريفًا كاملًا لنظام لم يعد موجودًا — والـ SPEC المرجعي (36 وكيلًا) أقدم منهما جميعًا.
الإصلاح
تحديث الشارة والجدول وقسم الوكلاء (وكذلك SPEC-multi-agent-architecture.md أو الإشارة بأنه superseded).
الثقة
شوهدت — قارنّا نص README بالخرج الفعلي للأوامر.
4. لا robots.txt ولا sitemap.xml ولا llms.txt — تطبيق عام لا يخبر محركات البحث والذكاء الاصطناعي بشيء معرّض للخطر
أين
public/ — الفحص الحي أعاد 404 للثلاثة جميعًا (/robots.txt، /sitemap.xml، /llms.txt).
التناقض
README يُقدَّم كمنتج عام «صُنع بحب للمحتوى العربي» مع نشر على Render، لكن لا خريطة للاكتشاف. /admin.html يُخدَم 200 لعامة الناس وبدون robots.txt يبقى مؤهلًا للفهرسة (حمايته الوظيفية قائمة — فهو 401 بلا توكن على مستوى API — لكن وجوده في محركات البحث غير مرغوب).
الإصلاح
إضافة الملفات الثلاثة في public/: robots يمنع /admin.html و/api/، وsitemap للصفحة الرئيسية، وllms.txt يوصف الأداة ونقاطها للوكالات الذكية.
الثقة
شوهدت — استجابات 404 حية من الخادم المقلع.
5. خمس ثغرات «high» أخرى في التبعيات (sharp/libheif، @xmldom/xmldom) معرّض للخطر
أين
npm audit --omit=dev: 11 ثغرة إجمالًا (1 critical، 5 high، 5 moderate). أبرزها sharp ≤0.35.4 (ثغرات libvips/libheif — مسار معالجة صور OCR عبر @xenova/transformers) و@xmldom/xmldom (حقن XML — عبر معالجة الملفات).
المسار من الخارج
مستخدم يرفع صورة (OCR) أو ملف XML/EPUB فتُعالَج بمكتبة بها ثغرة معالجة مدخلات.
الإصلاح
npm audit fix يدويًا مكوّنًا مكوّنًا (الـ fix --force ينزل transformers لإصدار قديم — لا تفعلها). اختبر OCR وملفات بعد كل ترقية.
الثقة
شوهدت — خرج audit الحالي.
6. قفل الأدمن يفشل-مفتوحًا (fail-open) عند خطأ مخزن العدّادات معرّض للخطر
أين
server/server.js:216 — «أي خطأ في المتجر → fail-open». مع REDIS_URL في الإنتاج، انقطاع Redis يعني تعطّل القفل وخلو الطريق أمام تخمين ADMIN_TOKEN (يتبقى حد heavyLimiter: 10/دقيقة — ليس بسيطًا لكنه كافٍ لجملة مفتاح ضعيفة مع الوقت).
الإصلاح
fail-closed لمسار الأدمن تحديدًا (خطأ المتجر ⇒ 503 مؤقت)، أو على الأقل fail-open مع حد صارم ثابت في الذاكرة كطبقة ثانية.
الثقة
شوهدت في الكود — سلوك موثّق ومقصود، لكنه يعطي نتيجة غير آمنة في بيئة موزّعة.

💡 ملاحظات معرفية (لا فعل مطلوب)

7. شارة README «providers-6» لا تضبط عاملًا متغيرًا للعلم
عدد المزوّدات الفعلي يعتمد على المفاتيح في .env (6 مسجّلة في الكود). الرقم صحيح عند تعداد السجل؛ فقط يظل ديناميكيًا بحكم الإعداد.
8. ADMIN_TOKEN قصير يُنبَّه ولا يُمنع للعلم
الخادم يحذّر عند الإقلاع فقط (server.js: «ADMIN_TOKEN قصير < 16») — قرار مقصود موثّق لتجنب كسر نشرات قائمة. مقبول مع وجود القفل التدريجي.
9. Swagger معطّل افتراضيًا — اختيار صحيح يُنصح بإبقائه للعلم
SWAGGER_ENABLED=false افتراضيًا فلا تُفضح خريطة المسارات على النشر العام. موثّق في README ومطابق للكود.
10. كاش Service Worker v7 يشمل admin.html للعلم
public/sw.js يخزّن /admin.html في PRECACHE — سلوك مقبول (الصفحة نفسها بلا بيانات)، لكن لو أضفت robots لاحقًا فلا تعارض بينهما.
11. `.env.example` مطابق للادعاء (161 سطرًا) للعلم
عددنا الأسطر فعليًا: 161 — أدق ادعاء في README، بُرمته حرفيًا.
12. امتدادات الملفات من المستخدم مُعزَلة عن مفاتيح التخزين للعلم
نقطة صعبة أُحسن التعامل معها: routes-projects.js:120-134 ينظّف الامتداد إلى [a-z0-9]{8} ويدفن الاسم الأصلي في meta — أي اجتياز مسار عبر filename مُغلق من المصدر. (قاعدة AGENTS.md مطبّقة فعليًا.)

⚠️ ما لم يُفحص — بصراحة

  • مزوّدات الترجمة الحية — لم نترجم شيئًا حقيقيًا (استهلاك حصص مجانية). فُحصت مساراتها بالكود والاختبارات فقط.
  • الدبلجة الصوتية E2E — تحتاج ffmpeg + فيديو حي + دقائق معالجة؛ اختُبرت منطقها عبر الـ 655 اختبارًا لا عبر تنزيل حقيقي.
  • النشر على Render/Docker فعليًا — يوجد Dockerfile وrender.yaml، لكن لم نبنِ الصورة أو نشغّلها. ثغرة protobufjs أعلاه تهم هذه البيئة تحديدًا.
  • اختبار المتصفح التفاعلي — لم نفتح الواجهة في Chrome ونجرّب التدفقات يدويًا (يُغطى جزئيًا باختبارات الواجهة وui.test).
  • اختبار الأحمال — سلوك الخادم تحت ضغط متزامن عالٍ (موازاة، ذاكرة) لم يُقس.
  • مراجعة أمنية شاملة لا تُثبت الأمان أبدًا — فهي تُظهر ما فُحص ومتى، لا ضمان خلوّ.
