1️⃣ الحكم العام

💬 مشروع MVP ناضج فنيًا وأكثر أمانًا من المتوسط — قابل للنشر، مع دَين تقني وفجوة طموح واضحين وموثَّقين ذاتيًا.

الكود يعمل فعليًا (لا محاكاة): 6 مزوّدي ترجمة بسلسلة احتياط، خط أنابيب دبلجة حقيقي (ffmpeg mux/mix)، محرك مهام (jobs) بحدود تزامن، قاعدة SQLite، وحماية SSRF من أعمق ما رأيته في مشروع بهذا الحجم (IPv4/IPv6 + صيغ التفافية + DNS rebinding). في المقابل: ثغرة أمنية حرجة في تبعية غير مباشرة بلا إصلاح جاهز، وserver.js أصبح هشًّا (ترتيب وسيطات حسّاس يعتمد على تعليقات لا فرض بنيوي)، والمشروع بعيد كثيرًا عن رؤية «استوديو دبلجة كامل» (لا صوت مستنسخ، لا مزامنة توقيت صوتي، لا تحرير ترجمات، لا مصادقة مستخدمين) — وهذا موثَّق بصدق داخل CURRENT_STATE.md نفسه، وهي ميزة نادرة: المشروع لا يخفي نقصه.

2️⃣ ما تم بشكل جيد 🎉

  • ثقافة اختبار مبنية على حوادث حقيقية: CHANGELOG.md يوثّق أن مسار الترجمة الأساسي (/api/translate-stream) كان معطّلًا كليًا في المتصفح بينما 248 اختبار وحدة كانت تمرّ — والإصلاح لم يكتفِ بترقيع العلّة بل أضاف tests/smoke.test.js الذي يستخرج كل مسار /api من كود الواجهة فعليًا ويتأكد أنه مسجَّل في Express، فيفشل تلقائيًا إن تكرر النمط. هذا مستوى نضج هندسي أعلى من المعتاد في مشاريع MVP.
  • حماية SSRF شاملة نادرًا ما تُرى بهذا العمق: server/ssrf.js يغطي نطاقات IPv4/IPv6 الخاصة، عناوين البيانات الوصفية للسحابة، الصيغ الالتفافية (عشري/سداسي/ثماني للعنوان)، IPv4-mapped/6to4/Teredo داخل IPv6، والأهم: يغلق ثغرة DNS rebinding عبر تمرير العنوان المُتحقَّق منه مباشرة إلى دالة اتصال undici بدل إعادة حل الاسم (نافذة TOCTOU كلاسيكية في أدوات الجلب من روابط المستخدم).
  • مصادقة الأدمن مصمَّمة بعقلية مهاجم: كوكي httpOnly + SameSite=Strict + Secure في الإنتاج بدل localStorage (يمنع تسريب XSS)، مقارنة توكن ثابتة الزمن (timingSafeEqual)، وإغلاق افتراضي آمن: بلا ADMIN_TOKEN ⇒ 503 لا مسار مفتوح.
  • ترتيب وسيطات Express موثَّق بدقة جراحية ومحروس باختبار (tests/middlewareOrder.test.js): مسارات SSE قبل compression() (وإلا يُخزَّن البثّ ولا يصل)، حدود حجم الجسم قبل express.json() العام، حدود الطلبات الثقيلة قبل موجّهات الدبلجة كي لا تُنفَّذ عمليات ثقيلة تحت حد عام متساهل.
  • معمارية مزوّدين قابلة للتوسّع فعليًا لا نظريًا: الترجمة (Google→MyMemory→Libre→Gemini→DeepL→zen) والـ STT (Gemini→captions→Whisper) بسلسلة احتياط + تبريد (cooldown) بعد فشل متكرر يمنع ضرب حصة ميتة داخل نفس الطلب.
  • أمان تشغيلي إضافي: كل استدعاء ffmpeg عبر execFile بمصفوفة وسائط (لا shell)، مسارات مشاريع/ملفات مُطهَّرة بـ regex + فحص startsWith على المجلد الجذر، تخزين الملفات بمفتاح مولَّد لا باسم المستخدم مباشرة.
  • فشل آمن (fail-open/fail-closed) مدروس مكانًا بمكان: عطل متجر حد الطلبات (Redis) يسقط للذاكرة ويسمح بالطلب بدل انهيار الخادم؛ غياب msedge-tts يعطّل الصوت العصبي دائمًا بتحذير واحد بدل قاطع يعيد المحاولة بلا أمل (مذكور في التزام 7ee3372 الأخير).

4️⃣ مراجعة أمنية (OWASP-محور)

✅ محصَّن وتحقَّقتُ منه بالقراءة الفعلية

  • SSRF: تغطية استثنائية (انظر القسم 2) + قفل DNS rebinding.
  • Injection: كل استدعاء عمليات خارجية (ffmpeg/yt-dlp) عبر execFile بمصفوفة، لا سلسلة shell أبدًا.
  • Path traversal: فحص صريح لبادئة المسار + regex على أسماء المشاريع/الملفات.
  • Auth timing attack: crypto.timingSafeEqual لتوكن الأدمن، وطول متساوٍ يُفحص أولًا لتفادي رمي الاستثناء المكشوف للتوقيت.
  • Secrets في الاستعلام: ?api_key= يُرفض عمدًا كمصادقة (يظهر في السجلات/Referrer) — رأس x-api-key فقط.
  • CSP: فعّالة بتوجيهات صريحة (لا unsafe-inline للسكربت، السكربت المضمَّن السابق نُقل إلى theme-init.js).
  • CORS: قائمة سماح صريحة (CORS_ORIGIN) بدل cors() المفتوح.
  • Rate limiting: على كل /api كخط أساس + حدود أثقل للعمليات المكلفة (دبلجة/OCR/TTS)، مع مضاعِف لحاملي مفتاح API صالح.

⚠️ لم يُفحص أو مقبول كقيد MVP صراحة

  • لا صلاحيات وصول للمشاريع: أي شخص يعرف معرّف مشروع يقرؤه — لا مصادقة مستخدمين إطلاقًا (موثَّق كقرار مقصود لغياب حسابات في الـ MVP).
  • حمولات TTS/OCR ضخمة لكل مقطع: لم أُجرِ اختبار إجهاد فعليًا في هذه الجلسة.
  • سباق تنزيلين متزامنين لنفس المشروع: لم يُفحص تجريبيًا.
  • الثغرة الحرجة في protobufjs (القسم 3): لم أُقيّم قابلية الاستغلال الفعلية (هل مسار الوصول من مدخلات مستخدم غير موثوقة يصل فعليًا إلى فكّ Protobuf؟) — يحتاج فحصًا مخصصًا قبل اعتباره مغلقًا أو مقبولًا.
  • حد طول 16 حرفًا لـ ADMIN_TOKEN: تحذير فقط لا فرض — توكن قصير عمدًا من مشغّل النشر يبقى ممكنًا.

6️⃣ التوصيات (بالأولوية)

  1. قيّموا استغلالية ثغرة protobufjs الحرجة قبل أي نشر إنتاجي جديد — إمّا مسار ترقية مُختبَر لـ @xenova/transformers، أو تبرير مكتوب لقبول المخاطرة مؤقتًا (المدخل صوت/فيديو غير موثوق يستحق جدّية أعلى من ثغرات qs المتوسطة).
  2. وثّقوا قيد فقدان المهام عند إعادة التشغيل في README كسلوك متوقَّع للمستخدم النهائي، أو نفّذوا استعادة بسيطة من projects/ — البند مفتوح منذ أكثر من أسبوع بلا حسم.
  3. افصلوا تركيب المسارات في server.js إلى وحدة/دالة مستقلة مع تحذير بارز أعلى الملف يشير للاختبار الحارس — تقليل احتمال تكرار حادثة routes-sse.js 404 التاريخية مع أي مساهم جديد.
  4. خطة ترقية express@5 (تحل سلسلة ثغرات qs المتوسطة) كمهمة منفصلة مع اختبار انحدار كامل — لا ضمن إصلاح سريع.
  5. تحققوا من youtube-dl-exec فعليًا في بيئة النشر (ظهر MISSING بعد التثبيت النظيف هنا رغم كونه في package-lock) لضمان أن مسار التنزيل ليس صامت الفشل.
  6. إن كان الهدف التسويقي لاحقًا هو «استوديو دبلجة كامل»: رتّبوا فجوة القسم 5 في خارطة طريق صريحة (Speaker diarization → atempo sync → استنساخ صوت → محرر ترجمات) بدل تركها ضمنية في وثيقة تدقيق داخلية فقط.

7️⃣ ما فُحص وما لم يُفحص (صدقًا)

فُحص فعليًا بالتشغيل في هذه الجلسة: npm install نظيف كامل، npm test (534 اختبارًا)، node scripts/check.js (98 ملفًا)، npm run lint، npm audit --omit=dev، npm outdated، git status/log لنظافة الشجرة، وقراءة مباشرة لـ server.js، ssrf.js، adminAuth.js، youtube-studio.js (للتحقق من إصلاح تسرّب المؤقّت المذكور في مراجعة سابقة)، ومستندات CURRENT_STATE.md/CHANGELOG.md/plan.md/كل ملفات specs/*/action-required.md.

لم يُفحص في هذه الجلسة: تجربة متصفح حية (لا واجهة رسومية متاحة في هذه البيئة)، دبلجة فيديو حقيقي (ffmpeg غير مثبَّت هنا — اختبار E2E الوحيد المتجاوَز بيّن ذلك بوضوح)، اختبار إجهاد/تزامن حقيقي، تقييم استغلالية ثغرة protobufjs عمليًا، مراجعة سطر-بسطر لكل ملفات server/providers/ (78 ملف خادم إجمالًا — رُوجعت عيّنة الملفات الأكثر حساسية أمنيًا وحركيًا لا كل الأسطر).

الجملة الصادقة: هذا فحص شامل على مستوى المشروع (وليس تدقيقًا للسطر بالسطر لكل الشيفرة)، مبني على تشغيل فعلي للفحوصات الآلية وقراءة مباشرة للملفات الحرجة أمنيًا ومعماريًا — لا يُثبت خلوّ المشروع من كل عيب، لكنه يعكس حالته الحقيقية بأمانة اليوم.
